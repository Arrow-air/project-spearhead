# FDM, SITL and Flight Deck: changes relative to `main` (October 2026)

This page describes what the `fdm/pt15-model-update-2026-10-14` branch adds to the flight
dynamics model on `main` (July 2026: ADB v1.1, open-loop simulation, trim, stability analysis and a
model-only GUI). Engineering results are in
[Flight Dynamics note 0003](../../../../docs/information-note/phase-1/Flight-Dynamics/0003-PT1-5-Hover-and-Fixed-Wing-Assessment/information-note.md);
installation is in the [setup guide](setup_guide.md).

## Aerodynamic reference

- The Aero team confirmed (14 October) that `database.csv` was exported about (−0.1, 0, +0.15) m
  and the deflection tables about (0, 0, 0). The base table is restored to (0, 0, 0) once, then
  moments are transferred to the CG with `M_cg = M_ref + (r_ref − r_cg) × F`.
- Nondimit applies the 1.3 drag multiplier before its moment shift, so the restore is exact.
- Control increments are measured to ±15° at 10, 15 and 25 m/s and continued linearly to ±30°.
  Flight values flag any point beyond measured coverage.
- Open questions to the Aero team are in
  [note 0002](../../../../docs/information-note/phase-1/Flight-Dynamics/0002-Aerodynamic-Data-Clarification-Request/information-note.md)
  (AQ-01 CFD origin, AQ-12 elevator −20/−30°, AQ-18 speed dependence of the neutral cases).

## ArduPilot SITL integration

- Pinned firmware: ArduPlane **Plane-4.7.1**, commit `dbe79216`; other binaries are refused.
  `scripts/build_ardupilot_sitl.sh` builds it locally.
- JSON SITL in lockstep at 200 Hz. The firmware supplies PWM; the FDM supplies physics and
  sensors. Home is the Ankara test field (39.8582, 32.5460, 1125 m above sea level).
- The FDM sends a pitot airspeed consistent with its own density, so the firmware airspeed matches
  the model at 1.021 kg/m³. Hover thrust settings include the firmware's density compensation.
- The lift-pack voltage and current go to the firmware in the JSON `battery` field (generic LiPo
  curve, 45 mΩ, lift motors plus 1.5 A avionics). The firmware reads them only with
  `BATT_MONITOR = 4`, which is not yet set in the repository parameters (awaiting approval).
- Wind (steady plus 1-cosine gusts) acts on the air-relative velocity for aerodynamics, pusher
  inflow and pitot. Injected failures (lift motor out, pusher cut) act between the firmware outputs
  and the physics; the firmware is not told.
- Runners: `spearhead.sitl.quad` (hover hold, hover doublets, hover → FBWA), `spearhead.sitl.flight`
  (forward-flight doublets, FBWA, forward → hover), ground start (takeoff, hover, landing) and the
  `validate` / `smoke` / `serve` tools.
- One transition parameter set is frozen: the 9 October proposal (`first_transition_2026_10_09`).

## Flight Deck

`python -m spearhead.gui` (or `sh scripts/run_flight_deck.sh`) opens the Flight Deck at `/`, which
runs the firmware against the FDM. The model-only console from `main` is **Model Lab** under
Analyze (`/model-lab`).

- Plan: aircraft PT1.5, starting point, test, CG choice with its static margin, elevator trim and
  hover headroom; wind, gust and failure inputs.
- Fly: attitude view, flight values (airspeed, elevator, pusher current, lift-pack voltage and
  charge used, wind) and live alerts (beyond measured control data, pusher above 24 A, pack below
  3.5 V/cell, injected failure).
- Review: recorded flights, flight plots, and **Compare with aircraft** (overlay of a DataFlash log
  and parameter differences).
- Analyze: CG window over a list of CG positions.

See [Flight Deck test tools](flight_deck_test_tools.md) and
[ground-control functions](flight_deck_ground_control.md).

## Migration notes

- `AircraftParams()` defaults are unchanged from `main` (25 kg, ADB v1.1). The default 20 s
  open-loop run, `run_trim.py` and the `scenarios/pitch_doublet.yaml` run give results identical
  to `main`.
- New work on PT1 or PT1.5 should load a profile (`pt1_as_built` or `pt15`) instead of editing
  `AircraftParams` defaults. Profile results differ from `main` by design: density, aerodynamic
  table and reference, geometry, mass, inertia and damping all change.
- `python -m spearhead.gui` now opens the SITL Flight Deck; the former console is at
  `/model-lab`. The SITL needs `requirements-sitl.txt` and a local firmware build.
- The GUI requirements are pinned to NiceGUI 3.17–3.x.
- Generated outputs, `.DS_Store` files and Python bytecode are no longer tracked (including
  Nondimit build bytecode); local runs write under `.sitl/` and `artifacts/`, which Git ignores.
- The reference design's fixed-wing SITL configurations are marked "not physical": they use a CG
  0.45 m below the origin to make ADB v1.1 trim.

## Verification

- 561 FDM tests pass, from the repository root and from the FDM folder.
- ArduPlane 4.7.1 SITL at the PT1.5 target CG: hover hold, hover in 6 m/s wind with a 3 m/s gust,
  hover → FBWA (calm and 6 m/s headwind), and hover and 22 m/s doublets in all four axes; results
  in note 0003. A front-right motor failure leaves the attitude envelope 0.4 s after it starts, as
  expected for a quad-X.
- The firmware reads the battery feed (46.6 V, 83 A in hover) with a temporary
  `BATT_MONITOR = 4` overlay.
- The setup guide was followed from a fresh clone on Ubuntu 24.04 with Python 3.13.

- The elevator increments carry yaw and roll loads from the 15 m/s cases, extrapolated beyond
  ±5°; they require 2.1° of rudder trim at 22 m/s. Removing lateral loads from symmetric elevator
  increments is proposed in note 0003, not applied.
- SITL parameter alignment with the aircraft (battery monitor and failsafe, servo ranges, loop
  rate, voltage compensation), awaiting approval.
- Weigh and ballast PT1.5 to the target CG; CG z and inertia are estimates.
- Static thrust test of the pusher motor (KDE or MAD) and the wooden 20×12 propeller.
- The SITL drives virtual elevator and rudder channels; the two-surface V-tail outputs
  (SERVOn_FUNCTION 79/80) are not modelled yet.
- Repository-wide spelling and formatting checks still report earlier issues.
